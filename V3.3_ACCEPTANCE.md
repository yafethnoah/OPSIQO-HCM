# OPSIQO HCM v3.3 — Production Acceptance Checklist

## Dependency/build gate
- [ ] Generate and review `package-lock.json` from the approved npm registry.
- [ ] `npm ci` succeeds from the reviewed lockfile.
- [ ] `npm run release:gate` passes.
- [ ] `npm run typecheck` passes.
- [ ] `npm test` passes.
- [ ] `npm run test:rules` passes in the Firebase emulator.
- [ ] `npm run build` passes.
- [ ] `npm run ai:evaluate` and `npm run ai:governance-check` pass.
- [ ] `npm run preflight:production` passes.
- [ ] Authenticated `npm run uat:lifecycle` passes against the promoted environment.

## Enterprise federation governance
- [ ] Every production OIDC/SAML provider exists in Firebase Authentication / Identity Platform and has a matching OPSIQO provider profile.
- [ ] Provider creator/submitting reviewer cannot independently approve the profile.
- [ ] Provider cannot activate without a successful metadata test in the previous 30 days.
- [ ] `OPSIQO_ENABLE_ENTERPRISE_SSO=true` only after federation configuration is operationally approved.
- [ ] `OPSIQO_IDENTITY_HOSTS` contains only the exact public OIDC issuer/discovery or SAML metadata hosts required by approved providers.
- [ ] `OPSIQO_ALLOWED_ADMIN_PROVIDERS` explicitly lists permitted privileged HR/admin sign-in providers.
- [ ] Public provider discovery remains disabled unless the organization intentionally exposes provider names on the sign-in surface.

## JIT boundary
- [ ] Existing active memberships bypass new-user JIT creation and remain governed by normal OPSIQO RBAC.
- [ ] New JIT requires a verified email claim.
- [ ] New JIT requires an active worker matched through governed work-email evidence.
- [ ] Provider email domain, MFA and managed-device requirements are enforced.
- [ ] Automatic JIT requires at least one active explicit mapping and every matching auto-JIT mapping resolves to `employee`.
- [ ] Schema tests prevent `autoJitEligible=true` for manager/HR/admin roles.
- [ ] Ambiguous or elevated mappings produce a human access request rather than privileged automatic activation.

## Access governance
- [ ] Manual grants/role changes/revocations/reactivations require independent approval before execution.
- [ ] User cannot approve or execute their own access change.
- [ ] HR Partner can manage identity work but does not have `identity.approve`.
- [ ] Manager and employee roles do not have enterprise `identity.read`.
- [ ] Access-review campaigns cannot close with pending review items.
- [ ] Revocation decisions create governed access requests rather than silently disabling membership.

## SCIM provisioning
- [ ] Provisioning request references an approved active v3.2 `scim_users` outbound profile.
- [ ] Provisioning creator/submitting reviewer cannot self-approve.
- [ ] v3.3 native execution is limited to approved SCIM create requests.
- [ ] SCIM update/disable remains blocked unless a reviewed deployment-specific resource-addressing adapter is available.
- [ ] Outbound identity payloads continue through v3.2 staging/idempotency/transport controls.
- [ ] Provisioning approval is not treated as employment activation/termination authority.

## Identity assurance & privacy
- [ ] Identity account external subject values remain server-only; UI responses redact the raw subject.
- [ ] Session evidence stores hashed UID rather than raw token/session credentials.
- [ ] No password, ID token, refresh token, SAML assertion or OAuth secret is persisted by the Identity Hub.
- [ ] Reconciliation is run and orphan/inactive-membership identities are reviewed.
- [ ] Aggregate identity evidence exposed to AI contains no tokens, passwords, external subject IDs or individual review rationales.

## Firestore / operational acceptance
- [ ] All 13 identity collections/indexes deny direct browser read/write.
- [ ] `/identity` loads for authorized enterprise HR/admin roles.
- [ ] `/api/organizations/<orgId>/identity/dashboard` is included in Lifecycle UAT.
- [ ] `npm run identity:review` creates deduplicated governance notifications.
- [ ] Lifecycle and Enterprise Command Center surface identity-assurance risks only to appropriately permissioned actors.

## Decision boundary
Identity readiness is an operational assurance indicator. It is not an external security certification, legal compliance opinion, identity-proofing certification, or authorization for an employment decision.
