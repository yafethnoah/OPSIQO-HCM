# Upgrade to OPSIQO HCM v3.0

1. Back up Firestore and deployment configuration.
2. Generate/review the npm lockfile in an approved environment; do not reuse an untrusted partial lockfile.
3. Deploy the updated Firestore Rules before enabling v3.0 Command Center writes.
4. Confirm RBAC mapping for `commandcenter.read`, `commandcenter.manage`, `commandcenter.approve`, and `commandcenter.audit`.
5. Set `OPSIQO_RELEASE_VERSION=3.0.0` in the deployment environment.
6. Configure protected GitHub `production` environment values/secrets used by `.github/workflows/production-promotion.yml`.
7. Run the complete acceptance sequence in `V3.0_ACCEPTANCE.md`.
8. Open `/dashboard` as HR Partner and HR Admin to verify management/approval segregation.
9. Create initial platform SLO definitions using an approved monitoring source and record baseline measurements.
10. Create the first production release assessment only from trustworthy CI/runtime evidence.
11. Schedule `npm run commandcenter:review` using the existing protected automation-job mechanism.
12. Create and independently approve the first Board/Executive HCM snapshot after source-domain owners verify their data.

The upgrade adds server-only Command Center records; it does not migrate or overwrite existing HR, governance, diagnostic, privacy, assurance, strategy, resilience or organization-design records.
