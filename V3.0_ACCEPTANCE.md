# OPSIQO HCM v3.0 Production Acceptance Checklist

## Dependency / build gate
- [ ] Generate and review `package-lock.json` from the approved npm registry.
- [ ] `npm ci` succeeds from the committed lockfile.
- [ ] `npm run release:gate` passes.
- [ ] `npm run typecheck` passes.
- [ ] `npm test` passes, including v3.0 command-center tests.
- [ ] `npm run test:rules` passes.
- [ ] `npm run build` passes.
- [ ] `npm run ai:evaluate` passes.
- [ ] `npm run ai:governance-check` passes for the production organization.
- [ ] `npm run preflight:production` passes.
- [ ] `npm run uat:lifecycle` passes against the deployed production candidate.

## Enterprise Command Center
- [ ] `/dashboard` loads the Enterprise HCM Command Center for authorized HR/admin roles.
- [ ] Users without `commandcenter.read` fall back to the role-scoped Lifecycle Command Center.
- [ ] Nine permission-scoped domain nodes are represented when their underlying permissions are available.
- [ ] Enterprise HCM Index is visibly labeled operational-only and non-certifying.
- [ ] Cross-domain dependency edges are visible and do not mutate source records.

## Cross-module actions / segregation
- [ ] HR Partner may read/manage/audit but cannot approve.
- [ ] Creator/submitting reviewer cannot independently approve an action plan.
- [ ] All required tasks must be complete before action-plan completion.
- [ ] Independent authorized closure is required.
- [ ] Action plans do not directly call recruiting, separation, compensation, succession or other consequential worker mutation services.
- [ ] Completing a Command Center action does not automatically close the source-domain record.

## Data quality
- [ ] Data-quality snapshots preserve score, finding counts, sampled flag and finding IDs.
- [ ] Current Lifecycle diagnostic remains authoritative for live data-quality findings.
- [ ] Large-tenant sampling warnings remain visible.

## SLO / observability governance
- [ ] SLO direction, target, tolerance, current value, measurement source and window are documented.
- [ ] SLO breach calculation is deterministic.
- [ ] SLO approval is independent.
- [ ] Production SLO values are supplied by an approved monitoring source; manually entered values are not represented as automated telemetry.

## Release governance
- [ ] Production release assessment snapshots non-secret runtime readiness.
- [ ] Dependency install, typecheck, tests, Rules tests, build, AI governance and lifecycle UAT are all `passed` before gate status becomes `ready`.
- [ ] A blocked release assessment cannot be approved for promotion.
- [ ] Production release assessments require a traceable CI evidence URL/reference; staging may omit it.
- [ ] Production-promotion GitHub workflow is configured with protected production environment/secrets.

## Security / privacy
- [ ] `commandcenter.read/manage/approve/audit` RBAC is verified.
- [ ] Employee and Manager roles do not receive enterprise Command Center access.
- [ ] All seven v3.0 Command Center collections/indexes deny direct browser Firestore access.
- [ ] Board/AI integrations contain aggregate command-center evidence only.

## Operations
- [ ] `npm run commandcenter:review` produces deduplicated overdue-action, SLO-breach and blocked-release notifications.
- [ ] Board/Executive report snapshots require independent approval.
- [ ] Rollback procedure is tested in a non-production environment.
