# OPSIQO HCM v3.6.1 Production Closure Bootstrap & Evidence Runbook

## Purpose
v3.6.1 closes the operational gap between a source-validated release and a reviewed npm lockfile. It does not auto-approve dependencies and it does not auto-commit generated dependency state.

## Step 1 — Run the reviewed lockfile bootstrap
In GitHub Actions, manually run **OPSIQO v3.6.1 Reviewed Lockfile Bootstrap** from the exact release branch/commit.

Enter exactly:

```text
GENERATE_LOCKFILE
```

The workflow will:
1. refuse to run if `package-lock.json` already exists;
2. generate a lockfile with lifecycle scripts disabled;
3. run the dependency-free OPSIQO lockfile reviewer;
4. prove `npm ci --ignore-scripts` can consume the generated graph;
5. capture the npm dependency tree;
6. produce SHA-256 evidence and a review patch;
7. upload the artifacts;
8. **not commit or push anything**.

## Step 2 — Human dependency review
Download the workflow artifact and inspect:

- `package-lock.json`
- `artifacts/lockfile-review.json`
- `artifacts/npm-tree.json`
- `artifacts/package-lock.patch`
- `artifacts/lockfile-bootstrap.sha256`
- `artifacts/REVIEW_REQUIRED.md`

At minimum verify:
- package/root release is `3.6.1`;
- direct dependency versions match `package.json`;
- no unexpected git/local/file dependencies exist;
- no insecure HTTP resolution exists;
- lockfile integrity metadata is reasonable;
- the workflow source commit is the intended release source.

The reviewer then places the approved lockfile in the release branch, runs `npm run source:manifest:generate`, reviews the resulting exact-tree `SOURCE_MANIFEST.sha256`, and commits both files through the repository's normal code-review process. Protected CI uses `npm run source:manifest:verify`, which rejects hash mismatches and unexpected unlisted release files.

## Step 3 — Run protected production evidence closure
After the reviewed lockfile is committed, run **OPSIQO v3.6.1 Production Evidence Closure** and enter the required `RESTORE_TEST` authorization.

The protected workflow first re-runs the dependency-free reviewer against the committed lockfile and binds that review artifact into the final evidence bundle. It must then complete the actual `npm ci`, audit, Gitleaks, CodeQL, typecheck, test, Rules-test, production build, AI governance, preflight, deployed UAT, cloud DR capture, temporary restore, sentinel verification, RTO/RPO capture, cleanup, provenance and final evidence verification.

## Step 4 — Promotion decision
Promote only when the final production evidence bundle is ready and independently reviewed. Store the exact CI evidence URL/reference in the production release assessment.

## Rollback
v3.6.1 changes release tooling and active version metadata but does not require an HCM data-model migration. If the patch must be abandoned before production, revert the v3.6.1 tooling commit and retain v3.6.0. Never retain or commit a partially reviewed lockfile.
