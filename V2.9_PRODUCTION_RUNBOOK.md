# OPSIQO HCM v2.9 Production & Rollback Runbook

## Pre-deployment
1. Verify the ZIP/repository source against `SOURCE_MANIFEST.sha256`.
2. Generate/review/commit a trusted `package-lock.json`.
3. Run `npm ci`, typecheck, unit tests, Firebase Rules tests and production build.
4. Run AI evaluation/governance checks, production preflight and Lifecycle UAT.
5. Verify v2.9 Firestore server-only rules and RBAC in staging.
6. Back up configuration/rule artifacts and note the previous production release identifier.

## Deployment order
1. Deploy Firestore/Storage security rules and indexes.
2. Deploy backend/API changes.
3. Deploy frontend `/org-design` route.
4. Confirm `/api/health/ready` returns ready under production configuration.
5. Smoke-test Org Design with an authorized HR admin and verify manager/employee denial.
6. Run a non-consequential current-state snapshot test in staging/approved production test organization.
7. Enable `orgdesign:review` only after smoke tests pass.

## Smoke tests
- Authorized HR role can load `/org-design`.
- HR Partner can create/manage but cannot approve.
- Manager/employee cannot access enterprise Org Design.
- Direct browser Firestore access to all 13 Org Design collections fails.
- Snapshot rejects a backdated `asOfDate`.
- Decision-right approval fails when referenced role architecture is not approved.
- Scenario creation fails without an approved baseline snapshot.
- Restructuring planning approval fails while any required human review is pending.
- Restructuring approval fails when the approver is the review-determination recorder.
- Lifecycle shows structural/KPI/restructuring alerts to authorized roles.
- AI Copilot exposes only aggregate Org Design evidence to authorized users.

## Operational job
```powershell
$env:OPSIQO_JOB_ORG_ID="YOUR_ORG_ID"
npm run orgdesign:review
```
Run using the same scheduler/secret handling used for other OPSIQO governance jobs.

## Rollback triggers
Rollback or disable v2.9 exposure if:
- server-only Firestore denial fails;
- RBAC grants approval or read scope to unintended roles;
- independent-approval checks fail;
- Org Design APIs can mutate consequential individual HR records;
- build/tests/rules/preflight/UAT fail;
- production readiness fails after deployment; or
- material data-integrity defects appear in structure snapshots.

## Rollback procedure
1. Disable Org Design navigation/route exposure if immediate containment is required.
2. Stop scheduled `orgdesign:review`.
3. Redeploy the previous known-good application release.
4. Restore previous rules/index/config artifacts if the rollback requires it.
5. Do **not** delete v2.9 governance records merely to roll back code; preserve audit history unless an approved retention/disposition process authorizes deletion.
6. Verify health/readiness, security rules and prior-release lifecycle UAT.
7. Record the incident/change decision in the release/audit process before attempting redeployment.
