# OPSIQO HCM v3.6.1 Build Repair Runbook

## Recommended Windows validation
Use Node 22 and the reviewed lockfile shipped with this repair.

```powershell
node --version
npm --version
Get-FileHash .\package-lock.json -Algorithm SHA256
node scripts/review-lockfile.mjs
node scripts/source-manifest.mjs verify
npm ci --no-audit --no-fund
npm run release:gate
npm run typecheck
npm test
```

Expected reviewed lockfile SHA-256:

```text
F62675B5B65CF12844AD071AB3EB8FF47035E0963FE5EB8EA35B5BE0EB2BEAE5
```

## Firestore Rules prerequisite
Firebase Tools 15.24.0 requires Java 21+ for the emulator path used by this release.

Check:

```powershell
java -version
javac -version
```

If Windows is still on an older JDK, install Microsoft OpenJDK 21:

```powershell
winget install Microsoft.OpenJDK.21
```

Close and reopen PowerShell, then verify Java again and run:

```powershell
npm run test:rules
```

The shared `vitest.config.ts` detects `FIRESTORE_EMULATOR_HOST`, which Firebase sets for the emulator subprocess, so the Rules suite is excluded from ordinary `npm test` but runs under `npm run test:rules`.

## Production build gates
After typecheck, unit/integration tests, and Rules tests are green:

```powershell
npm run build
npm run ai:evaluate
npm run ai:governance-check
npm run preflight:production
```

Do not run Production Evidence Closure until all of these are green.

## Git workflow
Apply this repair on a dedicated branch based on the reviewed-lockfile branch/release branch. Do not mix unrelated feature work into the build-repair PR.
