# Upgrade to OPSIQO HCM v3.6 — Production Evidence Closure & Cloud DR Execution

## 1. Upgrade scope
v3.6 retains all v3.5 HCM, security, identity, integration and Platform Reliability functionality. It adds release-evidence closure rather than a new employment module.

New capabilities:
- Firestore PITR / scheduled-backup metadata capture and deterministic policy assessment;
- controlled temporary-database restore workflow;
- canonical sentinel SHA-256 verification;
- measured RTO/RPO evidence and cleanup status;
- final production-evidence bundle with artifact hashes;
- Workload Identity Federation / Firebase Admin ADC support;
- dedicated CodeQL and Gitleaks production gates;
- corrected unified production preflight;
- removal of hard-coded v3.5 version labels from SBOM/provenance generators.

## 2. Package scripts
```text
cloud:dr:capture
cloud:dr:sentinel
cloud:dr:exercise:capture
production:evidence:generate
production:evidence:verify
production:evidence:test
```

## 3. New/changed environment contract
```text
OPSIQO_RELEASE_VERSION=3.6.0
OPSIQO_FIREBASE_ADMIN_AUTH_MODE=service_account|adc
OPSIQO_PRODUCTION_EVIDENCE_REF=
OPSIQO_CLOUD_DR_EVIDENCE_REF=
OPSIQO_DR_EXERCISE_EVIDENCE_REF=
OPSIQO_CLOUD_DR_REQUIRE_PITR=true|false
OPSIQO_CLOUD_DR_REQUIRE_SCHEDULED_BACKUP=true|false
OPSIQO_CLOUD_DR_MAX_BACKUP_AGE_HOURS=36
OPSIQO_DR_SENTINEL_DOCUMENT_PATH=
OPSIQO_DR_SENTINEL_EXPECTED_SHA256=
OPSIQO_DR_TARGET_RTO_MINUTES=
OPSIQO_DR_TARGET_RPO_MINUTES=
```

`adc` is intended for managed Google workloads or WIF-authenticated CI. It does not bypass IAM: the workload identity still requires the exact cloud permissions needed by the operation.

## 4. Required migration before production
v3.6 does not remove the long-running dependency gate. Before production:
1. generate/review/commit `package-lock.json` in a network-enabled environment;
2. regenerate `SOURCE_MANIFEST.sha256` after the lockfile is committed;
3. configure protected CI environments and Google WIF;
4. configure a safe DR sentinel and expected digest;
5. run the cloud metadata evidence workflow;
6. run the controlled production evidence closure workflow;
7. independently review the final bundle and store the approved evidence references in the deployment configuration.

## 5. No data migration
v3.6 does not require a Firestore application-data migration. Existing Platform Reliability records remain valid. Cloud evidence artifacts are generated by CI and may then be referenced/recorded through existing governed Platform Reliability processes.

## 6. Rollback compatibility
Application rollback to v3.5 does not require deleting v3.6 evidence artifacts. Retain them as audit evidence. If a v3.6 controlled restore created a temporary database, confirm it has been removed before closing the exercise.
