# OPSIQO HCM v3.1 Production Acceptance Checklist

## Dependency/build gate
- [ ] Generate and review `package-lock.json` from the approved npm registry.
- [ ] Commit the reviewed lockfile and use `npm ci` thereafter.
- [ ] `npm run release:gate` passes.
- [ ] `npm run typecheck` passes.
- [ ] `npm test` passes.
- [ ] `npm run test:rules` passes.
- [ ] `npm run build` passes.
- [ ] `npm run ai:evaluate` passes.
- [ ] `npm run ai:governance-check` passes.
- [ ] `npm run preflight:production` passes.
- [ ] `npm run uat:lifecycle` passes against the target environment.
- [ ] Production promotion evidence includes a traceable CI/workflow reference.

## Connector governance
- [ ] Connector creator/submitting reviewer cannot independently approve the connector.
- [ ] Authenticated connectors store only an approved secret-provider reference; no inline credential is persisted.
- [ ] Dashboard/API read output does not reveal the secret reference location.
- [ ] HTTP connector base URLs pass HTTPS, public-address and production allow-list checks.
- [ ] SCIM profile is used only with the SCIM protocol declaration.
- [ ] Connector activation is approval-controlled.

## Contract/schema governance
- [ ] Contracts declare JSON Schema 2020-12.
- [ ] Runtime validation is labeled `opsiqo-json-schema-subset-v1`; no unsupported full-spec claim is made.
- [ ] Breaking compatibility changes contain substantive review notes before approval.
- [ ] Contract creator/submitting reviewer cannot self-approve.

## Exchange reliability
- [ ] Connector-scoped idempotency hash prevents duplicate run creation.
- [ ] Plaintext idempotency keys are not persisted.
- [ ] Trace/correlation IDs are recorded.
- [ ] Valid inbound records remain server-only staging records.
- [ ] Invalid records omit payload data and generate governed dead-letter evidence.
- [ ] A rejected staging record does not prematurely terminate the active batch/run.
- [ ] Reconciliation variances require governed review/acceptance/resolution.
- [ ] `npm run integration:review` emits deduplicated connector/dead-letter/reconciliation alerts.

## Consequential-use boundary
- [ ] Integration routes contain no direct Worker/Employment/Compensation/Recruiting/Separation/Succession mutation path.
- [ ] Staging acknowledgement does not apply the payload to a source-of-record collection.
- [ ] Any eventual worker mutation must be performed through the responsible domain service and its existing authorization/business rules.
- [ ] Aggregate AI evidence contains no credentials or staged worker payloads.

## Privacy/security
- [ ] All integration collections/indexes deny direct browser reads/writes.
- [ ] HR Partner does not receive `integration.approve`.
- [ ] Manager and Employee do not receive enterprise integration permissions.
- [ ] Production external integrations are blocked unless the approved egress-host configuration is present when enabled.

## Enterprise integration
- [ ] Integration readiness appears in Lifecycle for authorized users.
- [ ] Integration is a domain node in the Enterprise HCM Command Center.
- [ ] Privacy/AI → Integration and Integration → Lifecycle risk dependencies are present.
- [ ] `/integrations/dashboard` is included in lifecycle UAT.
