# OPSIQO HCM v3.4 Production & Rollback Runbook

## Pre-promotion
1. Generate/review/commit `package-lock.json` in an approved networked environment.
2. Run `npm ci`, typecheck, tests, Firebase Rules tests, build, AI evaluations/governance, `preflight:production`, `release:gate`, and integrated UAT.
3. Review Security Operations RBAC and Firestore-denial tests.
4. Confirm enterprise SSO/Integration v3.3/v3.2 controls remain satisfied.

## Production security configuration
```text
OPSIQO_RELEASE_VERSION=3.4.0
OPSIQO_ENABLE_SECURITY_OPERATIONS=true
OPSIQO_SECURITY_EVENT_INGEST_SECRET=<secret-manager value, >=32 random chars>
OPSIQO_SECURITY_EVENT_INGEST_ORG_ID=<single-tenant org id>
# or use OPSIQO_SECURITY_EVENT_INGEST_SECRETS_JSON for per-org secrets
OPSIQO_SECURITY_SIEM_HOSTS=<exact approved public hosts>
```
Keep the ingest secret in the deployment secret manager. Do not place it in Firestore, source, connector metadata or browser environment variables.

## Monitoring
- Run `npm run security:review` on the approved governance cadence.
- Monitor critical incidents, high/critical security events, candidate session anomalies, privileged MFA gaps, overdue key/break-glass rotation and overdue recertification.
- Confirm approved SIEM exports use an active REST-push integration profile whose connector host is present in `OPSIQO_SECURITY_SIEM_HOSTS`.
- Treat readiness scores as operational indicators only.

## Incident handling
1. Create/triage a governed Security Incident.
2. Document containment and recovery plans.
3. Use Identity Hub for any access changes; use Privacy/Regulatory queues for notification/legal questions.
4. Preserve audit and security-event evidence under applicable retention/legal-hold requirements.
5. Resolve then independently close the incident.

## Rollback
1. Disable `OPSIQO_ENABLE_SECURITY_OPERATIONS` if external event ingestion/exchange must be halted.
2. Rotate the affected per-organization secret in `OPSIQO_SECURITY_EVENT_INGEST_SECRETS_JSON`, or the bound single-tenant `OPSIQO_SECURITY_EVENT_INGEST_SECRET`, if compromise is suspected.
3. Revoke/rotate external SOC/SIEM credentials at the provider/integration secret manager.
4. Do not delete incident/audit evidence merely to roll back application code.
5. Restore the prior verified application release and rerun readiness/UAT.
