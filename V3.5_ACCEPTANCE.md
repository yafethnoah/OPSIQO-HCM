# OPSIQO HCM v3.5 Production Acceptance — Software Supply Chain, SRE & Disaster Recovery

## Dependency / build gate
- [ ] `package-lock.json` is generated from the approved npm registry, reviewed and committed.
- [ ] `npm ci` succeeds from that exact lockfile.
- [ ] `npm audit --audit-level=high` has no unresolved release-blocking finding, or an independently approved exception exists.
- [ ] `npm run security:static-scan` passes and dedicated CI SAST/secret-scanning evidence is retained.
- [ ] `npm run supplychain:sbom` produces reviewed CycloneDX inventory evidence from the committed lockfile.
- [ ] `npm run typecheck`, `npm test`, `npm run test:rules`, `npm run build`, AI governance checks, preflight and integrated UAT pass.
- [ ] Build provenance and build artifact are retained from the protected CI workflow.

## Supply-chain governance
- [ ] SBOM evidence is independently verified before being counted as verified.
- [ ] Dependency vulnerability, secret, SAST, licence/container/IaC scans have evidence references and independent approval where used for release assurance.
- [ ] Build provenance identifies builder, build type, source digest, workflow/invocation, build timestamps, artifact digest and CI evidence.
- [ ] No SLSA level is claimed unless a separately assessed, signed CI provenance implementation supports that claim.
- [ ] Bounded OPSIQO source-pattern scanning is not treated as a substitute for dedicated SAST/secret scanning.

## Backup / restore / DR
- [ ] Approved backup policy covers every production data/service tier in scope.
- [ ] RPO/RTO targets are approved and tied to service/business requirements.
- [ ] Current backup evidence exists and is independently verified.
- [ ] Restore tests verify integrity and record actual RTO/RPO results.
- [ ] Disaster-recovery plans have owners, dependencies, recovery sequence, communication/escalation and next exercise date.
- [ ] DR exercises record target vs actual recovery results, gaps, actions and independent review.
- [ ] Backup/PITR configuration is verified in the actual cloud/Firebase environment; OPSIQO records evidence but does not infer cloud capability from configuration text.

## SRE / operations
- [ ] Approved platform SLOs have an authoritative monitoring source, measurement window, target, tolerance/error budget and owner.
- [ ] SLO breaches create review/action signals; they do not trigger employment actions.
- [ ] High/Critical configuration drift is reviewed against an approved baseline.
- [ ] Critical platform incidents have containment/recovery evidence, root cause, corrective actions and an independently reviewed postmortem before closure.
- [ ] Platform Reliability review automation is scheduled and notification deduplication is verified.

## Security / access
- [ ] Employee and manager roles do not receive enterprise `platform.read` permission.
- [ ] HR Partner can read/manage/audit but cannot independently approve Platform Reliability records.
- [ ] All v3.5 platform collections/indexes deny direct browser Firestore access.
- [ ] Platform Reliability APIs do not directly invoke recruiting, separation, compensation, succession, performance or worker-mutation services.

## Production configuration
- [ ] `OPSIQO_RELEASE_VERSION=3.5.0`.
- [ ] `OPSIQO_ENABLE_PLATFORM_RELIABILITY=true`.
- [ ] `OPSIQO_BACKUP_EVIDENCE_MODE` is one of `firebase_pitr`, `external_backup`, or `governed_manual` and accurately reflects the approved evidence model.
- [ ] `OPSIQO_PLATFORM_MONITORING_SOURCE` identifies the approved monitoring/evidence system.
- [ ] Existing v3.4 Security Operations, v3.3 Identity, v3.2 Integration, App Check, MFA, AI and egress controls remain satisfied.

## Decision boundary
- [ ] Platform readiness is described only as an operational reliability/security indicator.
- [ ] No UI/report claims certification of disaster recovery, SLSA level, secure development, SBOM completeness, regulatory compliance or guaranteed availability.
- [ ] Security/reliability events cannot independently discipline, terminate, rank, compensate or otherwise make a consequential employment decision.
