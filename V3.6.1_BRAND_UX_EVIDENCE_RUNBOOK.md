# OPSIQO HCM v3.6.1 — Brand/UX/Evidence Hardening Runbook

## Apply the overlay
From the existing v3.6.1 repair branch, stop the dev server and expand the overlay at the repository root. Do not copy `.env.local` into source control.

## Preserve the reviewed dependency graph
Confirm:

```powershell
Get-FileHash .\package-lock.json -Algorithm SHA256
node scripts/review-lockfile.mjs
```

Expected reviewed lockfile SHA-256:

`F62675B5B65CF12844AD071AB3EB8FF47035E0963FE5EB8EA35B5BE0EB2BEAE5`

## Dependency-aware verification
Use Java 21+ for Firestore Rules tests, then run:

```powershell
npm ci --no-audit --no-fund
npm run release:gate
npm run typecheck
npm test
npm run test:rules
npm run build
npm run ai:evaluate
npm run security:static-scan
```

If production AI governance data is configured:

```powershell
npm run ai:governance-check
```

## Firestore deployment
This hardening removes the redundant `analyticsSnapshots.snapshotDate` single-field composite index. Deploy the corrected rules/index configuration:

```powershell
firebase deploy --only firestore --project gen-lang-client-0021694027
```

## Runtime UAT
Verify at minimum:
- OPSIQO wordmark/icon appear on sidebar, sign-in, setup, prehire and browser/app icon surfaces.
- Sidebar and main content scroll independently on desktop.
- Navigation groups collapse/expand and the compact sidebar remains usable.
- People and Audit Trail never show a false empty state while requests are still loading.
- Command Center and governance modules display `Not assessed` when evidence coverage is below the minimum threshold.
- Integration with zero configured connector/runtime evidence is not presented as healthy readiness.
- Security with zero evidence is not presented as 100% healthy.
- KPI labels/values do not collide at desktop/tablet widths.
- Organization switching still reloads organization-scoped data.

## Final exact-tree closure
After all dependency-aware tests pass:

```powershell
Remove-Item .\.next -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item .\tsconfig.tsbuildinfo -Force -ErrorAction SilentlyContinue
Remove-Item .\firestore-debug.log -Force -ErrorAction SilentlyContinue
node scripts/source-manifest.mjs generate
node scripts/source-manifest.mjs verify
npm run release:gate
```

Then review `git status --short`, stage only intended source/config/brand assets and the regenerated `SOURCE_MANIFEST.sha256`, and commit on the repair branch.
