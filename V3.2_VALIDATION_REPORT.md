## Runtime hardening verified
- REST/SCIM resource paths must be relative, traversal-free and remain beneath the approved connector base path.
- HTTPS/SFTP endpoint validation rejects embedded credentials, localhost, private/non-public IPv4/IPv6 and mapped private IPv6 targets.
- Production endpoints require an exact approved `OPSIQO_INTEGRATION_HOSTS` allow-list when external integrations are enabled.
- Static adapter headers cannot supply authorization/API-key, Host, Content-Length or hop-by-hop transport headers.
- Terminal governed HTTP errors are not reclassified as retryable network failures.
- Retry count/backoff is bounded by the approved adapter profile; circuit-breaker state is persisted server-side.
- Inbound HTTP response bodies and outbound runtime payloads are bounded to 5 MB; OAuth token responses are separately bounded.
- Governed file exchange is constrained to connector-specific Firebase Storage prefixes and a 5 MB inbound file limit.
- SFTP remains fail-closed behind an explicit deployment-provider interface; no native/unverified SFTP transport is claimed.
- Scheduled execution is inbound-only, protected by a short lease, and uses deterministic per-occurrence idempotency.
- Scheduled outbound auto-sourcing from consequential HCM domain records is prohibited.

## Signed webhook governance
- Connector must be active, protocol `webhook`, and have exactly one active `webhook_hmac` profile.
- Connector authentication mode must be `hmac_secret` with a server-resolved secret reference.
- HMAC-SHA256 is computed over `timestamp + "." + rawBody` using constant-time comparison.
- Webhook timestamp acceptance is limited to five minutes.
- Webhook body is bounded before JSON parsing.
- Server-only signature state prevents concurrent duplicate processing.
- Successfully completed duplicate deliveries return the prior receipt/run result idempotently rather than reprocessing.
- Failed processing stores bounded rejection/error metadata and allows a controlled retry within the timestamp window.
- Raw webhook body and raw signature are not persisted in operational receipts.
- Accepted data remains contract-validated server-only staging; the webhook path cannot directly mutate worker/employment records.
