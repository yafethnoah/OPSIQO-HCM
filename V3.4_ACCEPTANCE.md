# OPSIQO HCM v3.4 Production Acceptance — Security Operations, Zero-Trust & Cyber Resilience

## Dependency/build gate
- [ ] Reviewed `package-lock.json` exists and is committed.
- [ ] `npm ci` succeeds from the approved registry.
- [ ] `npm run typecheck`, `npm test`, `npm run test:rules`, and `npm run build` pass.
- [ ] AI governance, production preflight, release gate and lifecycle UAT pass.

## Security Operations governance
- [ ] `securityops.read/manage/approve/audit` roles are reviewed; HR Partner has no independent approval authority.
- [ ] Employee and manager roles have no enterprise Security Operations permission.
- [ ] All Security Operations collections/indexes deny direct browser Firestore access.
- [ ] Security event evidence stores hashes/summary metadata rather than raw IP/session/token/credential material.
- [ ] Security-event signals cannot directly change employment status, discipline, performance, compensation, succession or other consequential HR records.

## Zero-trust / privileged access
- [ ] Privileged elevation is time-limited to <=24 hours and requires MFA.
- [ ] Security approval does not directly grant an HCM role; downstream Identity Hub governance remains required.
- [ ] Break-glass controls identify a vault reference only; credentials are never stored in OPSIQO records.
- [ ] Break-glass activation duration is bounded and credential-rotation/exercise evidence is reviewed.
- [ ] Privileged access and access-recertification approvals are independently authorized.

## Incident response
- [ ] Security incidents require documented containment/recovery plans and independent approval.
- [ ] Critical incidents are visible in Lifecycle and Enterprise HCM risk views.
- [ ] Privacy/regulatory review flags trigger qualified review rather than automatic legal conclusions.
- [ ] Incident closure requires resolved state and independent closure authority.

## SIEM/SOC event ingestion
- [ ] Security event ingress uses a per-organization secret map or a >=32-character single-tenant secret explicitly bound to one organization ID.
- [ ] Signed ingress validates HMAC-SHA256 over `timestamp.rawBody`, a five-minute freshness window, and a 1 MiB body limit.
- [ ] Signed-ingress replay index uses a processing lease; completed duplicates return the existing event idempotently, rejected attempts may be retried within the signed freshness window, and expired replay indexes are removed by governance review.
- [ ] `OPSIQO_SECURITY_SIEM_HOSTS` is populated when external Security Operations exchange is enabled in production; SIEM export itself independently enforces the exact allow-list and only uses an active governed REST-push profile.

## Credential/key rotation and recertification
- [ ] Key rotations cannot verify without completion evidence and independent verification.
- [ ] Overdue key rotations and break-glass rotations create governed notifications.
- [ ] Access recertifications track population and exception counts and require independent closure.

## Production acceptance
- [ ] `/security-operations` loads for authorized roles.
- [ ] `/api/organizations/{orgId}/security-operations/dashboard` is included in lifecycle UAT.
- [ ] Enterprise Command Center includes the Security Operations risk node/dependencies.
- [ ] AI Copilot receives aggregate security metrics only, never raw security-event identifiers or worker-level conclusions.
