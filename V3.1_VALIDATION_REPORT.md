## Additional hardening verified
- Connector credentials are represented only by approved secret-provider references; inline values are prohibited.
- Integration dashboard redacts the secret-reference location to `[configured]`.
- Connector-scoped idempotency keys are persisted only as SHA-256 hashes; plaintext idempotency keys are not stored in the run ledger.
- A record-level dead letter no longer prematurely terminates an otherwise active batch/run.
- Valid inbound records are server-only staging records and generic integration APIs do not apply them to Worker/Employment or other consequential HCM collections.
- Rejected staging records omit raw payload data and retain only validation/hash/error evidence.
- Reconciliation variances have a separate governed review/acceptance/resolution lifecycle.
- Integration readiness is included in the Lifecycle dashboard for authorized actors.
- Integration is a tenth Enterprise HCM Command Center domain node.
- Cross-domain edges include Privacy/AI → Integration and Integration → Lifecycle.
- Governed AI evidence receives only aggregate integration metrics; no connector secret reference or staged worker payload is provided.
- Lifecycle UAT includes `/integrations/dashboard`.

## Mandatory production sequence
Run in an approved networked Windows/CI environment:

```powershell
npm install --registry=https://registry.npmjs.org
# review and commit package-lock.json
npm ci --registry=https://registry.npmjs.org --no-audit --no-fund
npm run release:gate
npm run typecheck
npm test
npm run test:rules
npm run build
npm run ai:evaluate
npm run ai:governance-check
npm run preflight:production
npm run uat:lifecycle
```

Production promotion must also carry a traceable CI/workflow evidence reference.
