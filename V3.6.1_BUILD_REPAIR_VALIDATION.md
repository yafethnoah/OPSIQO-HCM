## Source repairs applied
1. Added `vitest.config.ts` with the same `@/* -> ./src/*` resolution used by TypeScript.
2. Normal `npm test` excludes `tests/firestore.rules.test.ts` when no Firestore emulator is present. When `FIRESTORE_EMULATOR_HOST` is set by `firebase emulators:exec`, the Rules suite is not excluded.
3. Career succession arrays/callbacks now carry explicit domain typing.
4. Compliance document arrays now preserve `EmployeeDocument` contextual typing.
5. Employee-experience membership filtering no longer depends on an implicit-any Firestore document parameter.
6. Governance 1–5 likelihood/impact values are narrowed only after Zod validation.
7. Integration reconciliation no longer declares `runId` before a spread that can overwrite it; the authoritative loaded run metadata wins.
8. Onboarding Firestore result mapping has an explicit document parameter type.
9. Organization membership rows use an explicit `(OrganizationMembershipSummary | null)[]` contract and a valid null-removal type guard.
10. People Analytics suppressed segment metrics are explicitly `Record<string, number>`.
11. Platform Reliability Firestore save records are constrained to object records, and service-objective action handling now explicitly narrows the `measure` action.
12. Recruiting list functions now publish concrete return types so callback parameters are contextually typed.
13. Safety screening explicitly returns `SafetyReviewStatus`; validated 1–5 hazard ratings are narrowed to their domain types.
14. Security Operations normalizes optional country code before entering a callback closure.
15. Production-readiness tests set `NODE_ENV` through `Object.assign`, avoiding TypeScript 7's readonly environment-property error.
